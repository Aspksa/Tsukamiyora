# Tsukamiyora RAG — первая версия

Локальная база SQLite FTS5, без Docker и отдельного сервера БД. Вызов Cloud.ru не требуется для индексации и полнотекстового поиска.

## API (localhost)

- `POST /api/rag/documents`: JSON `{"id":"note-1","title":"Заметка","text":"Текст документа"}`. Обновляет документ, только если текст изменился.
- `GET /api/rag/search?q=память&limit=5`: полнотекстовый поиск, фрагменты и `citation` с ID источника.
- `GET /api/rag/context?q=память`: короткие фрагменты для будущей передачи в LLM.
- `POST /api/rag/relations`: `{"subject":"A","relation":"uses","object":"B","sourceId":"note-1"}`.
- `GET /api/rag/relations?subject=A`: связи объекта.
- `POST /api/rag/facts`: `{"subject":"A","predicate":"version","value":"1","sourceId":"note-1"}`. Возвращает другие значения того же предиката для проверки противоречий.

Все данные хранятся в `data/tsukamiyora.sqlite`, которая уже включена в существующий механизм резервного копирования.

## Ограничения текущего этапа

Это полнотекстовый RAG, не векторный поиск: нет эмбеддингов, семантического поиска, LLM reranking и генерации ответов. Источники добавляются через API; автоматическое чтение PDF/DOCX и фоновые обходы каталогов ещё не подключены. Графовые связи и факты добавляются явно, а не извлекаются автоматически. `context` возвращает локально найденные фрагменты, но пока не отправляет их в Cloud.ru. API привязан к localhost и не предназначен для публикации в интернете без аутентификации.

Запуск тестов: `node --test tests/rag.test.js`.

## Индексация локальной библиотеки

`npm.cmd run rag:index -- "D:\\Library"` — однократное индексирование файлов .txt, .md, .markdown, .json, .csv и .log. Изменения индексируются инкрементально по SHA-256 содержимого. Файлы больше 1 МБ и символические ссылки пропускаются; за один запуск обрабатывается максимум 2000 файлов. Операция не отправляет данные в облако.

Индексатор запускается вручную. Автоматический фоновый обход, извлечение текста из PDF/DOCX, OCR и семантические эмбеддинги ещё не реализованы. Рекомендуется индексировать только доверенные папки: найденный текст рассматривается как данные, а не как команды.

## Автоматическая индексация

При старте сервера создаётся локальный файл `data/rag-settings.json` (если его ещё нет) и папка `data/library`. Индексация этой папки запускается автоматически при старте, затем каждые 30 минут. В настройках можно изменить `folders` на абсолютные пути локального M.2, `intervalMinutes`, `maxFiles`, `maxBytes` или выключить механизм через `enabled:false`. После редактирования настроек перезапустите сервер. Данные остаются локальными; Cloud.ru не вызывается. Изменения существующих документов индексируются повторно, неизменённые пропускаются.

Текущие ограничения: PDF/DOCX, OCR, эмбеддинги и генерация ответов Cloud.ru ещё не подключены.

При полном успешном обходе папки индексатор удаляет из поискового индекса записи о файлах, удалённых с диска. Если обход был ограничен `maxFiles` или возникли ошибки чтения, удаление записей пропускается во избежание потери знаний. Полнотекстовый поиск читает актуальные данные SQLite без долгоживущего кеша результатов.

## Диагностика

`GET /api/rag/status` возвращает число источников, фрагментов, графовых связей и фактов. При ошибках чтения каталогов индексатор сохраняет ранее проиндексированные документы вместо их удаления. Статистика не содержит текста документов.

## Retrieval pipeline

`GET /api/rag/retrieve?q=...` выполняет локальную нормализацию запроса, FTS5 поиск и повторное ранжирование по покрытию терминов. `GET /api/rag/context?q=...` возвращает найденные фрагменты с проверенными идентификаторами источников и дедупликацией. `GET /api/rag/status` включает метрики `retrieval` (запросы, количество результатов, пустые поиски, задержка).

Поле `modeUsed: lexical` намеренно показывает реальный режим. Семантические эмбеддинги, гибридный векторный поиск, LLM reranker, агентные циклы, автоматическое извлечение сущностей и Cloud.ru ещё не реализованы. Проверка цитаты подтверждает существование исходного фрагмента, а не истинность утверждения. Метрики хранятся в памяти процесса и сбрасываются при перезапуске.
