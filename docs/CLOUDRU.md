# Cloud.ru — настройки Tsukamiyora

Откройте локальный адрес `http://127.0.0.1:4177/settings`.

1. В личном кабинете Cloud.ru создайте сервисный аккаунт с доступом к Foundation Models.
2. Создайте API-ключ именно для сервиса **Foundation Models** и скопируйте Key Secret (позже он не показывается).
3. В настройках включите Cloud.ru, вставьте ключ и нажмите **Сохранить**.
4. Нажмите **Загрузить модели** — выполняется `GET https://foundation-models.api.cloud.ru/v1/models`.
5. Выберите модель из списка и нажмите **Сохранить**.
6. Нажмите **Проверить ответ модели** — это реальный тест `POST /v1/chat/completions`, который может тарифицироваться.

**Статусы:** `not_checked` — не проверено; `online` — список моделей доступен; `model_online` — выбранная модель ответила; `error` — ошибка подключения.

**Типовые ошибки:** 400 — неверные параметры; 401 — ключ недействителен; 403 — недостаточно прав; 404 — модель не найдена; 409 — модель недоступна; 429 — лимит; 500/502/503/504 — ошибки сервера, шлюза или тайм-аут. При 429 не отправляйте запросы бесконечным циклом.

Ключ хранится только в `data/cloudru-settings.json` (папка `data/` исключена из Git). Браузер получает лишь признак `configured`; сервер отправляет ключ Cloud.ru по HTTPS. На Windows права доступа к файлу дополнительно зависят от ACL каталога — не делитесь папкой `data` и настройте доступ к ней средствами ОС.

**API:** `GET/POST /api/cloud/settings`, `GET /api/cloud/models`, `POST /api/cloud/test`, `POST /api/cloud/chat`. Последний принимает `{"messages":[{"role":"user","content":"Привет"}]}`. Генерация пока не подключена к пользовательскому чату автоматически. Локальный HTTP API не имеет аутентификации: запускать его следует только на loopback и не публиковать через прокси или туннели. Проверка Origin ограничивает браузерные запросы с других сайтов, но не заменяет полноценную авторизацию.
